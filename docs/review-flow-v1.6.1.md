# 1.6.1：完整性与升级门槛复核

日期：2026-10-15。复核基线为 Kenxu `eef4420` 和 Ansible `0c08531`，两端与 GitHub 默认分支一致，工作区初始干净。

## 发现与修复

1. **增量缺号会被静默接受。** 1.6.0 仅要求新序号更大，这适用于原生累计报告，却不适用于 flow 增量。隔离测试从 seq 2 开始、或 1→3，都复现未拒绝。现在必须从 1 连续提交，缺批拒绝整个事务，不部分写入；幂等的已确认旧批重试仍成功。独立故障记录跨门户重启保留，心跳不能掩盖；补齐缺批及被拒绝尾批后才恢复覆盖。此修复不改原生总账。
2. **验收脚本可能带积压也返回成功。** 收紧为只读 SQLite 检查加最多 30 秒有界等待；原生或 flow 队列积压未清都阻止推广，正常进行中的一次上传可以等其结束。测试保证检查不会删除队列。
3. **旧安装入口缺少固定核心保护。** 旧 `deploy_meter.sh` 不能再绕过已验收 flow 的升级流程；在停服务／改文件之前拒绝，增加只读 `--preflight-only`。其他旧计量安装升级前先严格补报，出错恢复采集服务。没有在生产运行完整旧安装流程。

同时校正设计文档：生产用冻结的增量批次，不是离线模型的完整累计快照；落盘与 ACK 依赖顺序、重试和幂等，不声称跨进程同一事务；移除不存在的 `shadow_only` 配置说明。

## 范围与验证

- 先只读审计线上六个已记录 epoch：序号均连续，原生 `counter_reset` 事件为零。没有据此制造、补造或重写历史字节。
- 五台节点运行同一已验收核心，逐用户原生／观察累计夹取核对通过，原配置不变，UK 仍独立。没有替换或重启 Xray，也没有更改授权、凭据、分流与订阅。
- 新增真实 HTTP bearer、缺号拒绝、门户重启后故障保留、普通心跳不能抹掉缺口、按序恢复及原总账不变的回归。
- 核心二进制未变；本次修复门户接收保护、运维检查脚本与文档。长期 soak 和异常断电的未落盘窗口仍是已说明限制，不升级为“任意故障零丢失”。

本轮回归：56 项 Node 测试、25 项 Python 测试、完整 8 个隔离浏览器脚本通过；生产依赖 audit 未发现已知漏洞。上线后再次核对 6 个已有 epoch 无缺号、5 个采集器无积压、6 位用户 6/6 覆盖及管理端权限隔离，18 份实际订阅与账号／授权／密钥／历史账本保持一致。旧安装器只运行了只读预检，确认拒绝且原服务仍运行。

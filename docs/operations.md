# 部署与维护

本文针对现有的 Jetson + Cloudflare Tunnel 部署方式。先按 [README](../README.md#本地运行) 完成本地初始化，再接入已有节点与计量服务。

## 发布门户

1. 准备 Node.js ≥ 22.13、项目依赖与已构建的 `public/` 资源。
2. 将 `DATA_DIR` 放在 `public/` 之外，使用服务账号可写的绝对路径。该目录保存数据库、订阅签名密钥及运行数据，应限制其他账号访问。
3. 设置 `NODE_ENV=production`、准确的 `PUBLIC_ORIGIN` 和 `ADMIN_ORIGIN`。origin 只包含协议、主机与可选端口，不带路径或末尾斜杠。
4. 参考 [`donson-access.service`](../deploy/donson-access.service) 配置服务。示例中的 `jetson` 账号、项目路径和域名需要按部署环境替换。
5. 在 Cloudflare Tunnel 中配置公开主机名，服务指向 `http://127.0.0.1:4450`。浏览器到 Cloudflare 使用 HTTPS；Tunnel 到同机回环服务使用 HTTP。
6. 检查本地 `/healthz`、Tunnel 主机名映射和域名访问。管理端口 `4451` 通过 SSH 转发使用。

HTTPS 用户入口会在请求来自回环地址时信任 Cloudflare 设置的 `CF-Connecting-IP`，用于来源限流。此配置依赖“源服务仅绑定回环、公开访问经 Tunnel”的部署方式。私有管理端忽略转发 IP 头。

同一受信任入口通过 Cloudflare 的协议头区分访客使用的 HTTP／HTTPS。普通 HTTP 页面请求会跳转到 `PUBLIC_ORIGIN` 的 HTTPS 地址；密码提交、Bearer 请求及配置下载不会被自动重放，而是拒绝不安全的入口。不要仅依赖 HSTS：它不能保证从未访问过网站的浏览器第一次就使用 HTTPS。也建议在 Cloudflare 为站点开启 HTTPS 跳转。

登录与操作页面使用 `Referrer-Policy: same-origin`，不向外站发送引用地址，并兼容浏览器同源请求的 Origin 生成；订阅和配置下载继续使用 `no-referrer` 与 `no-store`。来源为空、`null` 或不匹配的写请求仍被拒绝，不以 Referer 或转发头替代 Origin／CSRF 校验。

## 私有管理入口

浏览器通过本地转发访问 `http://127.0.0.1:4451`，然后使用管理员账号登录。`ADMIN_ORIGIN` 必须与这个浏览器地址一致。

遇到“请求来源不匹配”，先确认用户端使用完整的 HTTPS 地址，管理端使用上面的 `127.0.0.1` 地址，不要混用 `localhost`、别名或其他端口。遇到“操作验证失败”，刷新当前页重新加载会话；其他标签页重新登录或管理员重置账号可能使旧令牌失效。不要通过允许 `Origin: null` 或关闭 CSRF 来解决。

Windows 可以使用仓库的桌面启动器：

1. 将 [`admin-ssh.config.example`](../deploy/admin-ssh.config.example) 复制为 `deploy/admin-ssh.config`，填写 Tailscale 主机、SSH 用户和密钥路径。私有配置已被 Git 忽略。
2. 在服务器配置专用的受限转发密钥。仅允许本地转发到 `127.0.0.1:4451`，并限制其 shell、PTY、代理转发和不需要的远程转发权限。密钥保存在仓库外。
3. 执行 `node deploy/launch-admin.mjs --check` 检查本地配置，再用 `node deploy/launch-admin.mjs --connect-only` 验证连接。
4. 执行 `deploy/create-admin-shortcut.ps1` 创建桌面快捷方式。双击后会检查／启动隐藏转发进程并打开管理页，网页仍需登录。

首次创建管理员使用 `pnpm admin create-admin <用户名>`。旧的 `open-admin.ps1` 属于首次初始化辅助脚本，不是日常桌面启动器。

## 节点计量与第三方中转

配置源使用显式的 `proxies` 列表，接受可选的 `proxy-groups`、`rules`、DNS 和规则提供器配置。当前版本不接受 `proxy-providers`；导入时会检查重复名称、无效引用和循环策略组。分发时只保留授权节点及可到达的组，移除控制器密码等不应交给用户的顶层字段。

网页维护入口统一在“节点管理 → 高级：更新私有配置源”，默认折叠。系统设置仅维护站点、周期和访问策略，规则在规则管理中维护；更新配置源后仍需核对授权和计量接入。节点重命名不只是改显示名称，会改变标识。

门户可以分发已授权的配置；逐用户计量还依赖服务器侧 Xray API、采集器、节点注册和独立凭据。可参考配套的 [Ansible 仓库](https://github.com/DonsonHH/my-ansible-playbooks)。仓库不包含实际节点注册 token 或私有上游配置。

- 一个物理核心注册一个采集器；共用核心的不同出口注册为逻辑线路。现有 SG2 与 UK 使用这种关系，两个出口分别计量。
- 第三方上游通过 Jetson 网关提供独立的用户入口。需要配置网关核心、回环 API 和固定路径的 VLESS/WebSocket 接入，原始上游凭据保留在服务器。
- 用户首次改密后，采集器同步其授权凭据。停用或到期会在成功同步时撤销新连接权限，已经建立的长连接可能持续到结束。
- 修改源 YAML 不会自动重写第三方网关的上游配置。节点重命名会改变节点标识，需要重新检查授权和注册。

原始共享凭据、直连流量和绕过受管入口的流量不纳入逐用户统计。采集器队列用于补报，但核心突然退出前尚未采样的字节仍可能丢失。

## 用量详情与来源归属（1.7.0）

先更新门户，再更新 [Ansible 采集器](https://github.com/DonsonHH/my-ansible-playbooks/blob/master/docs/kenxu-meter.md)。现有节点开启 `kenxu_meter_activity_enabled` 需要显式 bootstrap：先停止采集器、排空最后计数，再应用配置并进行一次核心重启。不要重建采集器注册或轮换用户 UUID。SG2 的 UK 逻辑出口仍按独立 email 和路由归属记录。

管理端的“用户管理”和“流量统计”使用同一个“用量详情”入口，分为三个按需加载的页签：用量总览（原账本、逐线路和每日合计）、流量去向（连接实际字节）、来源 IP（来源时间和估算地区）。节点卡片的“节点用量”则按节点下钻到用户，与单个用户的详情不同。操作日志仅记录管理员操作，不复制代理用量。

门户可设置 `GEOIP_DB` 为私有离线 Country／City MMDB 的绝对路径，服务启动时加载；更新库后重启门户。国家库通常没有城市信息，未知地区保留未知。默认不调用外部查询；数据库不随仓库分发，维护者负责库的来源、许可和更新。

流量去向只读 `flow_events` 的实际连接字节。按注册主域名合并，再对上传＋下载严格大于 10 MiB 的网站排序，显示前十；小额网站隐藏但显示小额合计，仍保留原计量。未知目标单列。可按 1／7／30 天、来源 IP 和目标筛选。旧 `groupActivity` 关联算法、口径切换和 `/api/admin/usage/users/:id/logs` 接口已删除；历史账本和有效来源记录保留，没有分类数据就显示暂无，不回退推算。

可选 `IPINFO_TOKEN` 必须通过服务端私有环境文件／密钥设施配置。1.5.2 起，管理员点击“查询 IPinfo 归属”调用固定的 **Legacy Free** `https://ipinfo.io/<ip>/json`，只允许该用户最近 30 天实际出现的公网来源 IP。密钥使用 Authorization 请求头，不放 URL、前端或仓库；拒绝重定向，限制响应体、超时与并发。成功缓存 7 天，失败退避 5 分钟；旧 Lite 缓存不会阻止首次补查省市。保存国家、省／州、城市和运营商／ASN；字段缺失保持未提供，不存坐标、邮编、hostname。清理缓存不删除计量账本。只使用有 Legacy 权限的令牌，不自动切换其他身份、无令牌查询或付费接口。官方标示有令牌免费 Legacy 为每月 50,000 次，实际额度以账号为准；权限不足／限额时返回可重试错误，保留离线信息。参考 [IPinfo 官方说明](https://support.ipinfo.io/hc/en-us/articles/34121895556242-Legacy-Free-API-vs-IPinfo-Lite)。

该可选查询会将来源 IP 发送给 IPinfo，不发送用户名、订阅或访问目标。上线前应告知使用者；删除服务端令牌并重启即可关闭外部查询，离线归属仍可用。1.7.2 用户端仅展示最近 IP 与国家、省市，不展示历史列表和 ASN；`GET /api/account/last-use` 只返回本人最近一条的少量字段且不触发外查。进入个人中心时，前端仅在缓存缺失时用原有 CSRF 保护的 POST 补查这一条 IP，复用 7 天缓存和 5 分钟失败退避，不查询整段历史。普通用户查询仍独立限流，无法查询其他用户或任意 IP。管理端详细来源、运营商和主动查询保留不变；目标网站与操作日志仍只限私有管理端。IP 地理归属是估算，VPN、移动网络、共享 NAT、Anycast 都可能让结果与设备所在城市不同。

采集器只发送经过校验的 IP、目标域名／IP、端口、传输类型与新连接数，不发送 URL、请求内容或原始日志。来源是实际代理入口的连接对端，不是网页登录 IP、出口 IP，也不应无条件信任未验证的转发头。共享 NAT／多设备／中转可能导致多个使用者共用一个公网 IP；账号归属仍由个人代理凭据确定。

门户启动和每小时清理 30 天外的使用元数据，查询严格限制最近 30 天；节点的持久重试队列同样脱敏超期元数据，但继续补报字节。节点原始 access 日志只限本机管理员和 Xray 读取，并按 30 天轮换。删除的是在线元数据，不重置历史用量；备份也应执行独立的受限访问和到期清理策略。

个人中心只在自己的最近使用 IP 后显示地区；管理端来源页默认一天，可切换 7／30 天。用户旧的本人来源列表接口为兼容保留，但新界面不调用它，也没有筛选、历史卡片或查询按钮。应向受邀用户说明该范围。绕过受管入口、JP 直连和 China@US 不计量备用线路无法记录，页面隐藏不能改变这一事实。

节点展示分组和国旗仅作用于网页：SG 主节点、US 主节点、其他线路。未注册采集器的直接交付线路不伪造计量，China@US 标明直连未计量；已注册但停用的普通受管线路仍按原有 fail-closed 逻辑处理。显示文本使用国家代码，卡片加载本地 SVG，不改订阅、授权 ID 或分流规则中的原名称。

## 连接检测与服务器监测

[`kenxu-node-checks.service`](../deploy/kenxu-node-checks.service) 独立运行连接检测，需要 Xray、curl 和私有 `DATA_DIR`。目前检测器支持源配置中的 VLESS/TCP/Reality 线路；不支持的传输会明确显示。默认每轮间隔 15 分钟，后台可调至 5–120 分钟。

检测从 Jetson 通过源节点请求小型 HTTPS 响应，记录时间和耗时。源配置改变会让旧检测失效，超时未更新的数据不会一直显示正常。第三方线路检测的是原始上游出口，公开网关和访问者网络还可能有各自的问题。

后台的基础设施监测需要在服务器设置 `MONITOR_ALLOWED_ORIGINS`，填写允许读取的 HTTPS origin，多个以逗号分隔；后台“系统设置”填写相同监测站的根网址。监测站需提供适配器兼容的公开 bootstrap 数据。适配器限制响应大小和重定向，缓存并返回选定指标。

## 分流规则与个人分配

1. 通过私有 SSH 入口登录管理端，打开“规则管理”，选择“全局默认规则”或某位普通用户。用户管理中的“配置规则”可直接进入对应用户。
2. 全局编辑器直接维护默认列表；用户可选继承、优先补充或独立方案。补充列表在全局列表前匹配，不能包含 MATCH；独立方案缺少 MATCH 时会保存当前可用兜底目标，没有合适目标时使用 REJECT。
3. 一行一条，使用 `DOMAIN-SUFFIX,example.com,DIRECT` 这样的逗号格式，不带 YAML 短横线。MATCH 只能是最后一条。支持常用域名、IP 网段、进程、GEOIP／GEOSITE、RULE-SET 等简单类型；不支持 AND／OR／NOT／SUB-RULE 嵌套表达式，也不接受匹配内容中的逗号。
4. 点击“校验并预览”检查格式、顺序和授权后的实际规则。预览不含节点凭据，不分配新 UUID、不保存草稿；它不是设备连通测试，也不会下载远程规则集验证网络可达性。
5. 想基于现有配置精调时，可“复制当前导出规则为独立草稿”。检查后点击“保存规则”，让用户在客户端手动更新订阅。规则提供器和策略组定义仍在私有 YAML 源维护，不能通过规则文本增加节点授权。

语法或策略错误返回行号，旧配置不变。另一个窗口更新规则、配置源或授权时，旧修订号不能覆盖新状态；重新载入后再编辑。退出与切换账号会清空编辑器和预览。审核日志只记录方案、数量与目标账号，不记录规则全文。

个人方案保存在 SQLite 的独立表，账号删除时随其清理；迁移不会改动原账号、节点 UUID、订阅签名或用量。默认未分配个人方案的用户继续继承全局。回退至旧代码会暂时不应用个人方案，完整数据备份仍保留；已分配独立方案后，应优先回退至支持该方案的版本，或先明确恢复继承，不能把旧代码忽略方案当作等价回退。

Clash 类 YAML 接收个人规则；Stash 使用同一方案并去除电脑进程规则；Shadowrocket 是节点订阅，其应用路由仍需在客户端设置。DNS、节点、策略组和规则提供器来自共享配置源，独立只指规则列表。

## 更新周期与访问限制

从 1.4.0 起，检测优先请求 Gstatic 的空响应 204，失败时使用 Cloudflare trace 回退，界面注明真实目标。HTTP 响应采用 curl 的 `time_starttransfer - time_pretransfer`，连接准备和全程则分别来自 `time_pretransfer`／`time_total`。不把进程运行时钟当作节点延迟，不通过除数或取最小值“美化”数字。它是 Jetson 经源节点的 HTTP 响应，不是访问者的 ICMP／本地客户端 URL 测试。

测量细节存入独立附表，保留原检测表的五字段接口；旧数据没有被改写，仍标记全程口径。新旧口径不应横向比较为“网络提速”。间隔仍为后台设置的 15 分钟默认值，网页刷新不会增加探测频率。

用户端的节点状态和订阅领取范围保持一致。受管节点除了节点授权，还须启用入口并完成该用户的个人接入；仅勾选授权不代表节点已经可领取。网页查询会同步当前节点范围与用户资料，管理员撤销或恢复授权后不需要用户重新登录。管理端节点状态保留全部源节点，便于检查尚未对用户开放的线路。

| 设置 | 默认值 | 含义 |
| --- | --- | --- |
| 网页查询 | 60 秒 | 读取已保存的用量与连接状态 |
| 订阅更新建议 | 720 分钟 | 响应头 `profile-update-interval: 12`；客户端已有自定义设置可能覆盖它 |
| 节点连接检测 | 15 分钟 | 后台定时检测，不由网页访客触发 |
| 用量采样 | 15 秒 | 采集器默认周期，上报可能因重试延后 |
| 月展示额度 | 100 GB | 展示比例，后台可修改，不触发流量停用 |
| 审计日志 | 保留 30 天 | 默认显示近 24 小时，可分页查看更多 |

用户与管理员入口分别使用十五分钟认证窗口：每账号 8 次、每来源 30 次、该入口和操作总量 120 次；成功登录清除账号计数，来源和总量计数保留。数据存入 SQLite，重启不会清空有效窗口。限制命中返回 `Retry-After`，不会永久禁用账号。完整行为见 [1.1.0 review](review-v1.1.0.md)。

## 备份、升级与回退

数据库启用了 WAL。复制前停止所有访问该私有目录的写入进程，通常包括门户与节点检测服务；采集器会暂时保留待上报数据。

1. 停止门户、节点检测及其他自行添加的写入者。
2. 复制整个私有数据目录，保留权限，包括 SQLite、WAL／SHM（如有）、`subscription.key` 和运行状态。
3. 在新的发布目录准备依赖、构建资源并完成检查。
4. 原子切换当前发布目录的符号链接，启动服务。
5. 验证公开／私有健康端点、账号、采集上报与节点检测，保留上一版本以便回退。

不要仅复制运行中的 SQLite 主文件，也不要在回退代码时覆盖新产生的用量和采集队列。若版本包含数据结构变化，应先核对向后兼容性。

## 失效线路退役

先备份完整私有数据目录，再在私有服务器环境中执行：

```sh
DATA_DIR=/absolute/path/to/private-data node src/admin.mjs retire-node '完整节点名称'
```

命令在事务内移除源节点、策略组成员和对应授权，停用逻辑计量线路；不会重置账号、会话、订阅签名或历史流量。若全局／个人规则直接引用该节点、其他节点依赖它、策略组将变空或它是最后一条线路，会拒绝执行，要求管理员先选择替代方案，不擅自扩大权限或改变分流意图。

已退役线路的凭据记录和计量身份保留，用于历史统计及旧采集队列。它如果是共用采集器最初的登记入口，只要仍有启用的同采集器线路，原采集令牌就继续有效；没有启用的线路后不再接受该令牌。不要手工删除登记行或轮换同组令牌，否则会影响其余线路。

采集器取得新配置后移除退役线路的客户端与分流。若中转配置中还有该线路的独立上游，应在确认没有剩余引用后，校验并同步移除持久配置及运行时出站；不要重建或更换其他出站标签。同步清理原始 YAML，避免后来重新导入失效入口。

所有已有订阅链接直接返回新配置，但客户端缓存不是远程可写文件。客户端按自身更新设置拉取（默认建议 720 分钟）；需要立即生效时手动“更新订阅”。仅下载的本地 YAML 要重新下载／导入。

## 受管线路改为隐藏直连

`meter_nodes.direct_delivery` 是显式的运维选择，与一般停用计量节点分开。值为 `1` 且 `enabled=0` 时，已获原节点授权和登记的账号收到原始直连参数，不再替换为网关凭据。`user_hidden=1` 从用户端节点状态和线路历史明细中隐藏该项；管理员仍可查询既有用量。仅设 `enabled=0` 不会启用共享凭据。

迁移前备份完整私有数据与相关中转配置，排空采集队列，再停止这条线路的计量。仅在该物理采集器没有其他启用线路时，停止并禁用对应中转与采集服务；不能影响同采集器中的其他线路。保留授权、登记、历史计量凭据和旧用量。直连参数必须交付给已授权客户端，隐藏界面不能防止用户查看配置文件。

客户端更新远程订阅后才改走直连。Clash 的辅助策略组可通过 `hidden: true` 隐藏；其他客户端是否隐藏分组取决于其界面支持。

已经直连、未注册采集器的备用线路，可在私有源节点上设置 `kenxu-user-hidden: true`。这只隐藏用户端节点列表和连接状态统计，管理员仍能查看该节点；授权、分流及客户端连接参数不变。门户会在导出配置前移除此内部标记，不向客户端注入特殊字段。

## 删除账号

一般停用账号即可阻止后续领取与新连接，同时保留用量历史。需要永久删除时，先备份并确认目标账号。

删除已停用的普通账号前，在同一数据库事务中调用 `store.meter.retireUserCredentials(id)`，记录其精确采集身份，再删除相关凭据和账号记录。Xray 可能保留旧计数，采集队列也可能尚未排空；缺少这些退役标记会使整批报告失败。标记应随用量数据保留。

## 故障排查

| 现象 | 优先检查 |
| --- | --- |
| 域名打不开 | 本地 `/healthz`、门户服务、Tunnel 服务映射、DNS |
| 管理页打不开 | Tailscale、SSH 密钥、本地 4451 端口和启动器配置 |
| 登录提示尝试过多 | 等待响应指定的冷却时间，再确认凭据 |
| 配置能下载但没有用量 | 节点是否受管、用户是否授权、采集器注册和报告是否更新 |
| 节点显示待更新 | 检测服务状态、最近检测时间、Xray/curl、源传输是否受支持 |
| 监测卡片为空 | 后台监测网址、服务器允许列表、bootstrap 格式和网络 |
| 删除账号后停止上报 | 是否保留了退役身份标记，采集队列是否在重试旧报告 |

检查日志时应隐藏订阅链接、认证头、UUID 和私有上游内容。不要在 Issues 中粘贴真实配置或数据库。

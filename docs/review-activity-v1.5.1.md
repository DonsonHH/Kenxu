# 1.5.1：网站合并总览与 IPinfo Lite

## 已确认的范围

先上线合并总览，不改任何 VPS 节点、代理路由或采集器；准确网站计量的节点改造留到下一步单独设计。原有 30 天元数据、长期计量账本、订阅和账号授权不变。

## 实现与 review

- 默认展示前 10 个网站关联值、实际区间用量、无新目标记录的区间用量，以及最近来源 IP。原始日志默认折叠，展开才请求，避免再堆满逐条记录。
- 使用 Public Suffix List 合并注册主域名；同站子域名合并，`co.uk` 和独立 `github.io` 等租户不会误并。IP 目标不猜测网站。
- 每个“用户＋分钟＋逻辑线路”对同一网站只计一次，汇总整个 1／7／30 天选定范围，不受原始明细第一页 30 条限制。存在多个网站时关联值可能重叠，因此明确标记不可相加，不画误导性占比饼图、不按连接数均摊。无新目标记录的持续连接保持未知。
- IPinfo Lite 实测和官方文档都只有国家、洲和运营商／ASN，不返回省市、坐标或具体住址；本版只使用 Lite，不调用付费端点。固定提供方、Authorization 头、服务端密钥、管理员与 CSRF 校验；仅允许该用户真实出现过的公网来源 IP，拒绝本地／保留地址及任意 URL。
- 管理员点击才对外查询，成功缓存 7 天，失败退避 5 分钟，并限制并发、超时、响应体和重定向；无密钥或查询失败时仍保留离线归属。浏览器、用户接口和 Git 仓库不含真实令牌。使用指南说明了 IPinfo 的信息披露范围，页面保留来源署名。
- 用户端仍只显示本人最近使用 IP，不增加 ASN 或网站日志。原生弹窗使用就地状态反馈，保留原有单一 Sonner 提示层。查询／筛选与账号切换隔离迟到响应，刷新后回到弹窗顶部。
- 最终 review 修正加载时修改筛选条件的竞态：请求期间锁定筛选控件，明细与当前已应用的总览条件保持一致；加载期间先展开明细时，待总览完成后自动补载。
- 两个 GitHub 仓库均核对远端；Ansible 无需修改，本轮不部署节点改造。备份保留长期账本与密钥，但排除访问元数据，避免备份延长其保留时间；回滚代码不覆盖新用量。

## 验证

- Node 后端 50 项回归通过，含主域名归并、去重／重叠、全范围汇总、30 天边界、权限／CSRF、来源范围、IPinfo 去重缓存与失败退避。
- 完整 8 个浏览器脚本通过，另复测新总览、按需明细、IPinfo 模拟查询、手机与深色模式。测试使用虚构账号、用量和模拟提供方，不将测试用户 IP 发给外部服务。
- 生产部署后对 1／7／30 天范围总量独立核对计量账本，对关联值用 SQL EXISTS 独立重算；实际订阅响应、账号和旧用量校验保留。

精确网站流量统计并未在本版实现或假装完成。国家／运营商信息也不代表设备所在的具体住址。

参考：[IPinfo Lite 字段与限制](https://support.ipinfo.io/hc/en-us/articles/34121895556242-Legacy-Free-API-vs-IPinfo-Lite)、[Xray 原生统计口径](https://xtls.github.io/en/config/stats.html)。

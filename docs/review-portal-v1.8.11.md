# 1.8.11：完整复核与住宅 IPv6 展示修正

2026-10-25。

## 本轮发现与修正

1. 住宅 IPv6 使用独立出站，但此前与 UK 同归为 `forwarded`，界面将它标为英国转发。现在由计量登记中的实际出站标签提供 `residential-ipv6` 类型，用户节点卡片、管理节点／授权入口和用量详情显示住宅 IPv6。UK 保持原有说明。没有改节点名称、UUID、账号权限、路由、原生计量或分类字节。
2. 私有部署里一条前置目标网段规则会使无关域名在命中后续规则前先做 DNS 查询。该规则已加 `no-resolve`，继续匹配已有的目标 IP；不再仅为尝试这条网段规则强制解析每个域名。两个指定域名的优先规则不变。具体私有源和备份保留在运行端，不提交仓库。
3. 上一版节点分类源码和卡片已更新，但独立打包的响应图仍使用旧分类。同步重建 `public/charts.js`，并在浏览器检查实际图表的前六条标签，确保 SG1／SG2／SG3／US1／US2／US3 顺序正确。

`no-resolve` 跳过额外解析；若目标 IP 尚未知，不会为了该网段规则主动解析域名。它没有把目标网段缩成单个 IP，也没有改变客户端的正常连接解析。参见 [Mihomo 官方说明](https://wiki.metacubex.one/config/rules/#no-resolve)。

## 验证

- 新增回归先复现住宅身份被标为 `forwarded`，修正后接口类型、UK 区分、总账与订阅不变的检查通过。
- 门户 81 项单元及接口测试通过。
- 隔离 Edge 浏览器覆盖用户节点、管理节点、授权弹窗和用量详情的住宅标签，同时核对实际打包图表的 US1／US2／US3 排序、UK 原有说明、隐藏备用、手机／宽屏排版及导出身份不变。
- 隔离 Mihomo 在本地测试 DNS 下复现原规则对无关域名的额外查询；修正后查询数为零。同组测试继续验证目标 IP、域名和域名后缀匹配，以及首选失效后回到默认线路、恢复后重新首选。测试没有连接或控制用户正在使用的客户端。
- 实际六个账号、三种格式的 18 份订阅按结构比对，本轮配置修正只增加网段规则的一个 DNS 标志，其余规则、组、凭据和授权不变。Shadowrocket 节点列表不变。
- 对部署仓库的 28 项 Linux 测试和真实 root／Xray 账号日志权限测试复核通过；GitHub 受跟踪文件树与本地提交逐项相符。没有再次修改或批量重启其他节点。

## 保持的设置

JP 继续移除，历史用量保留；US3 普通线路仍在三节点美国均衡内，个人账号保留直接选择 US3 的入口，住宅线路仍仅限指定账号。sticky-sessions 仍为原有 10 分钟策略。US3 优先回退依据客户端连通性探测，不代表对每个目标 HTTP 错误自动重放请求。

运行端账本、身份和订阅签名密钥通过变更前后基线比对保护。私有变更基线、原始配置、隔离测试输出和可恢复备份位于工作区已忽略的 `private/` 及 Jetson 私有目录。

# 1.8.1：双仓库复核与 AI 状态异常降级

日期：2026-10-16。起点为门户 `6477ecb`（GitHub main）和采集仓库 `a006c66`（GitHub master）。两个本地工作区起初干净，Git remote 与 GitHub 默认分支查询均一致。本轮范围是审阅上一轮操作并修正可复现问题，没有继续新增功能、改节点或分流。

## 发现与修正

| Before | After | Why |
| --- | --- | --- |
| 当前 JSON 故障没有任何可用时间字段时被过滤；缺失 incidents 列表被当成空列表 | 当前源校验失败、标未知，保留上次记录；历史附加源独立标不完整 | 格式不完整不是“没有故障”，不能因此制造正常结论 |
| 一份 RSS 有正常的已恢复记录及无效的故障条目时，只丢掉无效条目，可能显示未报告故障 | 任一事件链接、标识或发布时间无效时拒绝这份源，保留历史并标未知 | 只保留能解析的正常记录会造成选择性误报；不接受外站链接 |
| 浏览器读取门户失败后只显示错误文字，旧的绿色状态卡片不变 | 卡片降为当前待确认，明确提示“门户状态读取失败”；历史和上次服务项保留，成功重读后恢复 | 不把旧结论冒充当前，也不把访客到门户的故障混同官方来源／AI 服务故障 |

这些是隔离异常场景中确认的边界缺陷，不表示当时线上官方数据已发生这些缺字段或混合无效条目。本轮没有改写已有状态采样，前端读取失败也不会记作厂商宕机或触发上游外查。布局、主题、轻量过渡及既有 Sonner 实例保留；依据状态反馈原则修正的是信息含义，而非增加装饰动画。

## 复现与验证

- JSON 用同一只读采集接口注入当前故障缺时间／缺列表，先观察到 `operational` 而非 `unknown` 的失败，再修正通过。
- RSS 同时提供一个合法已恢复条目和一个带外站链接的进行中条目，先观察到 `no-incident` 的失败，再修正通过。
- 浏览器真实登录后拦截 `/api/ai-status` 返回 503：先观察到四张卡片仍保留旧状态，再验证全为未知、门户读取错误单独说明、历史保留、取消拦截后恢复，以及原有 401 清理行为。
- 门户完整 70 项 Node 测试通过；12 个隔离 Edge 浏览器脚本覆盖双端旧功能与 AI 状态，包含 390–3840 CSS 像素、深色、筛选、全零用量及完整 30 天趋势时间轴。Jetson 新发布目录复跑 70 项测试，四家真实官方源均可读取。
- 采集仓库完整 25 项 Python 测试通过；代码、部署门槛与文档本轮未发现需要修改的问题，保留 `a006c66`，不创建空提交。生产依赖审计未发现已知漏洞。两个 GitHub 仓库的 Actions 运行记录仍为空，不宣称 GitHub CI 通过。

## 线上与数据边界

发布前确认 v1.8.0 线上四个来源新鲜、服务 active。最近一小时实际取得 48 个采样桶，四个来源相邻桶间隔均为 300 秒；其中 Claude 有一次未知，后续已经正常恢复，未将该缺失样本改成正常或故障。此前 18 份实际订阅与账号、授权、凭据、规则、密钥、原账本及分类历史基线仍一致。只读覆盖检查为五个采集器／六条逻辑线路正常，没有重新部署或升级核心。

来源范围仍为 [OpenAI 官方状态](https://status.openai.com/api/v2/summary.json)、[Claude 官方状态](https://status.claude.com/api/v2/summary.json)、[AI Studio／Gemini API](https://aistudio.google.com/status) 与 [Grok 官方 RSS](https://status.x.ai/feed.xml)。Gemini 不以 Workspace／Vertex 替代。只读缓存、五分钟后台采集、30 天元数据、未知历史不推算 SLA 的边界不变。

已发布到 Jetson `20261016-v1.8.1-status-review`，只短暂重启门户，没有重启 Xray、检测、Tunnel、既有代理或修改环境配置。原 1.8.0 发布目录及 0600 一致性账本备份保留；备份副本去除来源／目标标签，不改在线数据，不用旧数据库覆盖新用量。

四个真实官方源均通过新解析器，取得后续约五分钟后台采集成功记录。验证读取只访问缓存／数据库，没有手动刷新上游来代替定时任务。发布后的 18 份实际订阅与账号、授权、凭据、规则、密钥及原账本、分类历史字节基线保持一致；临时诊断会话清理，不替换现有用户登录。

公开 HTTPS `/healthz` 回读 1.8.1；公网脚本、图表和样式哈希与本地相同，当前发布的 AI 源码与用户模块也逐文件匹配。HTML 仍为 `no-store, private`，严格去除唯一且原已存在的 Cloudflare analytics 脚本后与本地一致，未放宽 CSP。公开 AI 状态接口无登录返回 401。

本轮未发现其他需要修改的回归。厂商页面接口变化、个别请求故障以及长时间 soak 等限制仍存在；短时验收不能证明所有用户网络或所有 AI 功能都正常，也不声称任何过去异常都由本轮边界缺陷造成。

# 1.5.0：私有使用日志与最近使用 IP

## 范围与口径

管理端“用户管理／流量统计 → 使用日志”显示用户、逻辑线路、分钟、真实上传／下载，以及同期观测的新连接目标和来源 IP／估算地区。默认最近一天，支持 7／30 天、来源与目标筛选、稳定分页。用户端只在个人中心显示自己的最近使用 IP。

现有 Xray 用户计数器继续作为唯一字节账本，不新增另一套字节计费；stock Xray access 日志不提供逐目标的准确字节。因此不会把一分钟的全部流量重复算给同一分钟出现的每个域名。持续连接可以没有新目标，IP／域名并不证明具体前台应用；无法据此回溯开启前的用量成因。

不记录 URL 路径、正文或解密 HTTPS。来源是实际受管代理连接的对端，与网页登录、Cloudflare 请求头和出口地址不同。地区查询使用私有离线 MMDB，Country 库没有城市时不猜测城市。直连、不计量备用或绕过受管入口的连接不覆盖。

## Review 修正

- 观测数据与长期计量解耦，仍在原报告事务中校验采集器、email、用户和逻辑出口归属。未知身份整批回滚，精确退役身份跳过；旧客户端计量流程兼容。
- 报告序号、epoch、累计计数与重试去重保留。超过 30 天的队列元数据脱敏后仍可补报原字节，避免隐私清理造成重复入账或中断补报。
- 门户启动及每小时清理超期元数据；接口、筛选和翻页在分钟边界也严格限制 30 天。清理不删除历史流量账本。旧用量不补造访问记录。
- 节点解析器有持久 inode／offset 游标，与队列同事务；限制读取量、行长、目标数、IP 数和报告大小。超长行不会永久阻塞后续记录。日志本机私有并按 30 天轮换；copytruncate 的观测缺口不影响原字节计数。
- 无在线连接的账号返回原生 NotFound 是正常状态，不把它误报为接口故障；采集器忽略此类在线来源空缺，仍上报计数与真实 access 观测。
- 启用日志需要显式 bootstrap，一台核心一次重启；部署先排空旧计数。以后可用同一 playbook 接入新节点，保留原注册、UUID 与 UK 路由。
- 管理日志使用私有入口和管理员角色；普通用户不能读取自己或别人的管理日志。原生弹窗就地展示加载／错误，继续复用唯一 Sonner 提示层。
- 使用指南增加记录范围说明，清理已退役线路的教程文字，区分历史截图与当前隐藏辅助组。

## 验证

- 45 项 Node 后端测试：计量重试／重启、授权、来源安全、角色隔离、规则、日志分页与跨 30 天边界。
- 8 项 Python 采集器测试：原有路由保留、SG2／UK 隔离、解析与游标、超长行、超期队列脱敏且保留字节。
- 完整 8 个浏览器场景脚本通过，另复测新日志弹窗与 1280／1920／2560／3840 布局；390px 手机无页面横向溢出，宽表格内部滚动。截图使用虚构账号和保留示例 IP。
- `pnpm audit --prod --audit-level high`：无已知漏洞。
- 生产门户与 5 台物理采集器实际部署；6 条受管逻辑线路（包括 UK）使用个人受管凭据的低流量 HTTPS 204 检查通过。采集队列排空，管理 API 已收到真实来源、目标与地区，用户 API 仅返回本人最近使用 IP。
- 对生产可领取用户的 Clash／Stash／Shadowrocket 共 18 份真实远程响应做哈希对比，配置逐字节未变；账号、授权、规则、凭据、订阅签名及既有历史计量校验保留。

仅以观测开始后的数据辅助排查异常用量，不把元数据功能称为逐网站精确计费或历史流量成因的定论。

# Jetson 私有链式分流

此功能是可选的个人网络路径试用，仅向私有管理员和绑定账号交付。普通订阅的规则、凭据、授权和默认选项保持原样。

## 路径与使用

绑定用户在“我的订阅”中领取原版 YAML、Jetson 链式 YAML，或复制可自动更新的链式订阅。管理员在私有入口的“系统设置”中下载同一账号的两份配置。其他账号没有入口、能力字段或链式下载权限。

先连接 Tailscale，再在 Mihomo / Clash Meta 客户端导入链式版，保持**规则模式**：

| 命中规则 | 实际路径 |
| --- | --- |
| 原来的 DIRECT 公网规则，包括国内网站和 donson.top | 电脑 → Tailscale → Jetson → 国内互联网 |
| 原来的国外代理策略 | 电脑 → Tailscale → Jetson → 所选自有 VPS → 目标网站 |
| 内网、回环及 Tailscale 传输 | 本机直连，避免隧道套入自身 |
| 原来的 REJECT | 继续拒绝 |

链式版沿用已有分流与策略，不按域名后缀猜测所有网站的地理位置；原来有明确代理策略的网站继续按该策略执行。保留现有国内规则与个人规则，移除第三方未计量备用节点，只交付已授权、已接入个人计量且列入物理端点允许列表的线路。英国和住宅出口仍使用既有独立身份与出站。

首跳使用仅绑定 Tailscale IPv4 的 VLESS/XUDP 服务，传输加密由 Tailscale 提供。公网与 Cloudflare Tunnel 均不发布该端口。节点的 `dialer-proxy` 指向首跳；首跳自身明确使用本机 DIRECT。原 DIRECT 规则转换为 Jetson 出站，DoH 通过首跳访问；DNS 引导与代理服务器解析保留指定解析器。

这不是 Windows 系统流量捕获开关。系统代理仅接管遵循系统代理的程序；TUN 是否启用沿用使用者自己的设置。链式版适用于 Mihomo / Clash Meta，不提供 Stash 或 Shadowrocket 的链式转换。不要切到客户端的“直连”模式，否则会绕开链式规则。

## 私有配置

生产 DATA_DIR 中可放置 `jetson-chain.json`，权限 0600，目录 0700，且不得进入 Git 或公有资源目录。没有此文件时功能关闭。示例值均为虚构值：

```json
{
  "version": 1,
  "ownerUserId": "00000000-0000-4000-8000-000000000001",
  "gateway": {
    "server": "100.64.0.10",
    "port": 4465,
    "uuid": "00000000-0000-4000-8000-000000000002"
  },
  "endpoints": [{"server": "192.0.2.1", "port": 443}]
}
```

ownerUserId 必须是既有普通账号的不可变 ID；账号改名不会把权限转移给新建的同名用户。endpoints 是人工核实的自有物理端点允许列表；未来新增服务器需要复核后增补，不会因为名称带 US／SG 自动加入。

门户启动时读取配置，修改此文件后需要重启门户。通过私有 SSH 会话，在已确认设置和账号状态后执行：

```sh
sudo python3 deploy/install-jetson-chain.py --root /home/jetson/donson-access
```

安装器只维护自身的 systemd 服务、独立 Xray 配置和 KENXU_CHAIN 防火墙链，不覆盖已有 Xray 或采集器。要求已有可信 Xray 二进制、Tailscale、iptables 和 Python 3；部署前核对其路径。独立服务使用无登录系统账号，禁用访问日志，拒绝私有目的地址，仅接受 Tailscale 接口上的认证连接。每分钟的权限检查在账号被停用、过期、需要首次改密或私有状态读取失败时停止首跳；恢复账号后由管理员检查并手动启动服务。

停用此试用时，先停止并禁用 `kenxu-chain.service`、`kenxu-chain-owner-guard.timer`，再移走私有 JSON 并重启门户。保留历史账本。泄露首跳凭据时须更换 gateway.uuid、重新运行安装器并重启首跳及门户；只重置订阅链接不能撤销已经下载的首跳凭据。

## 计量与边界

到 VPS 的连接沿用绑定账号原有个人 UUID，仍由原节点记录。Jetson 首跳不注册第二个计量采集器，避免把同一笔传输重复加入用户账本。国内直出不会计入受管 VPS 用量；Jetson／Tailscale／运营商接口总量是另一口径。

Tailscale 可能通过 DERP 中继。它可能改善路径可达性，也可能增加延迟和限制吞吐；不能仅凭拓扑保证提速。测试应分别确认国内出口、每条 VPS 出口、规则命中、UDP、失败时无本机回退、普通用户无权限和正常订阅字节不变。

## 验证命令

```sh
pnpm test
pnpm build
pnpm test:chain
```

`test:chain` 使用虚构账号、临时数据库和独立浏览器，覆盖用户／管理员两份下载、其他账号的 API／订阅拒绝、退出清理与手机布局。真实出口测试使用独立内核、临时端口及私有导出，既不切换当前客户端，也不在公开报告保存订阅链接、UUID 或出口 IP。

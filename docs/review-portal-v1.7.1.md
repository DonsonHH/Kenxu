# 1.7.1：复核 1.7.0，修正会话与慢网交互

日期：2026-10-15。门户复核基线 `92a5f5e`，Ansible 基线 `abd6917`；初始工作区干净，均与 GitHub 默认分支一致。没有预设后续新功能，本轮只复核并修复已发现问题。

## Findings 与修正

### [P1] 会话失效后，来源详情请求没有立即退出

隔离 Edge 登录普通用户，删除该测试会话，再点“刷新来源”。真实后端返回 401，但旧页面仍处于登录状态，订阅字段未立即清空；原测试在等待登录页时稳定失败。服务端没有接受过期会话，问题是前端局部错误处理未统一执行退出逻辑。

现在所有受保护请求统一处理当前身份的 401：清空私有视图、订阅和来源，关闭管理弹窗，回到登录页。请求携带发起时的界面身份，旧账号迟到的 401 不能把后续登录的另一个账号退出。错误密码的登录请求不按“已登录会话过期”处理。管理员在编辑中遇到真实 401 的场景也覆盖了：不写入账号、关闭弹窗、清除草稿和授权列表。

### [P2] A 用户的迟到保存会关闭 B 用户的新编辑

在真实测试服务器成功保存 A，但暂缓浏览器收到响应；随后关闭 A、打开 B 并输入未保存的昵称。释放 A 响应后，原实现会重置同一个表单并关闭 B，导致草稿丢失。回读测试数据库确认仅 A 被保存，不是后台误写 B。

抽出共享表单生命周期模块，按打开批次、提交实例和登录身份判断响应是否还能操作当前编辑器。A 的服务器写入可正常完成并更新列表，但不能关闭、清空或解锁 B 的编辑；旧错误也不会写进 B 的错误区。重置密码和配置上传复用该保护。关闭重开会清理旧按钮／倒计时状态，服务器的认证和限流仍然有效，不把界面取消视为服务端撤销。

### [P2] 快速切换用量详情会被旧 close 事件清空

在同一事件循环内关闭 A 详情并打开 B，原生 `close` 事件稍后派发，原实现无条件 reset，导致 B 的详情空白。测试在等待 B 标题时稳定失败。现在只有弹窗确实仍关闭时才清理，重新打开的新详情不受旧事件影响。账号编辑／重置弹窗使用同样的检查。

## 回归方法

原失败命令：

```powershell
$env:PLAYWRIGHT_CHANNEL='msedge'
node test/browser-lifecycle.mjs
```

修正前分别捕获：真实 401 后仍无登录页、A 保存关闭 B 编辑、B 详情标题无法出现。修正后同一命令通过，并覆盖：

- 普通用户和管理员真实会话失效，私有数据立即清空。
- 新账号已登录时，旧账号的迟到 401 不会将其退出。
- A 迟到成功不清空 B 草稿，后台 B 资料也未变化。
- 快速切换用量详情，B 正确显示；关闭后内容仍清空。
- 模拟 429 的表单关闭后重开，不残留旧按钮倒计时；未放宽服务端限流。
- 页面无未捕获异常，测试账号和数据库均隔离清理。

本轮使用诊断流程先建立失败回归再修复；表单公共模块用于集中异步生命周期，而不是在每个按钮继续堆叠独立状态。通知沿用单一 Sonner 容器，当前会话过期提示由统一请求处理触发；管理弹窗内普通错误仍就地展示。

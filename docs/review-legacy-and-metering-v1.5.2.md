# 1.5.2：Legacy 省市与准确计量改造设计

日期：2026-10-15。门户升级与节点设计是两个独立交付：前者上线，后者不替换正在使用的节点核心。

## 上一步 review

核对 Kenxu main 与 Ansible master 的远端提交、源码、现有 API、授权隔离、分组算法、缓存、测试和生产状态。五台 Xray 均为 26.3.27，采集队列排空，SG2／UK 仍分开计量。原网站汇总仍是关联口径；没有把它伪装为精确网站字节，也不重写历史流量。

## Legacy Free

- 用户现有服务端令牌已实测具有 Legacy 权限，固定调用 `https://ipinfo.io/<ip>/json`，读取国家、省／州、城市、运营商／ASN。没有切到付费接口、匿名接口或其他提供方。
- 仍只接受管理员经 CSRF 验证后查询该用户近 30 天实际出现的公网来源 IP；不对外发送用户名、订阅或访问目标，用户端仍只看到本人的最近使用 IP。
- 成功缓存 7 天，失败退避 5 分钟。按 provider 区分旧缓存，避免旧 Lite 国家缓存阻止补查省市。相同已缓存结果不重新请求；旧库和用户账本无需迁移。
- 省市缺失就显示未提供，Anycast／VPN／共享网络结果只作 IP 归属估算，不等于具体住址。不保存返回的坐标、邮编或 hostname。
- Review 补上等价 IPv6 文本兼容、拒绝 scope zone 地址、非 2xx 响应体取消，以及 Legacy/Lite 字段形状隔离。错误原文和令牌不返回浏览器。
- 页面继续使用唯一 Sonner 提示层；原生弹窗的查询反馈在弹窗内显示。

## 节点设计交付

方案在 [Ansible 设计文档](https://github.com/DonsonHH/my-ansible-playbooks/blob/master/docs/kenxu-flow-design.md)，包含固定源码版本调研、Counter／连接生命周期接入位置、Vision/splice 时序风险、短连接最终值、落盘 ACK、幂等、未知量、独立校准、性能门槛和逐台回退步骤。只读 preflight 与离线 replay 模型可以运行；它们没有实现 Go 插桩或生产安装。

调研借鉴了 xray-exporter、V2bX、sing-box；未找到已核对范围内可直接代替当前拓扑并提供所需耐久、逐用户目标字节的成品。建议保留 Xray 协议与当前账号，从 US2 隔离环境先验证，再单独进入真实试点。不能仅凭分类合计等于原账本断言原账本正确，亦不能把源码风险直接认定为 hdc 历史异常的根因。

## 验证记录

- 53 项 Node 后端回归，含 Legacy 省市缓存、旧 Lite 失效一次、空城市、不匹配／过大响应、IPv6、权限和历史计量。
- 完整 8 个浏览器脚本回归；新增省市实际文字与缓存命中断言，普通用户不见管理端地理信息。
- Ansible 仓库 17 项 Python 回归，包含只读预检与 7 项离线计量契约测试。契约测试不等于实际快路径已通过。
- 发布前后对所有可领取用户的 18 份订阅响应做哈希核对，账号、授权、凭据、签名和既有计量保持一致；真实 Legacy 查询后再查命中缓存。

字段和免费额度以 [IPinfo 官方说明](https://support.ipinfo.io/hc/en-us/articles/34121895556242-Legacy-Free-API-vs-IPinfo-Lite) 为准；结果不能代表用户的具体物理地址。准确计量核心尚未上线，当前网页继续如实显示关联值。

# 1.8.10：US3 节点分类与路由维护复核

2026-10-25。

## 代码变更

节点展示模型现在识别 `Aether@US3`，与 US1、US2 一同放入美国主线路类别，按数字排序。用户端响应图、线路卡片和管理端共用该模型，节点原名、ID、授权与计量身份均不改。住宅或备用线路不因带有美国国旗就自动成为普通主线路。

没有修改客户端内核。当前 Mihomo 的 sticky-sessions 缓存固定 10 分钟，源配置保持原策略；不能通过增加一个未受支持的 TTL 字段改变它。参见 [官方策略说明](https://wiki.metacubex.one/config/proxy-groups/load-balance/) 和 [v1.19.32 源码](https://github.com/MetaCubeX/mihomo/blob/v1.19.32/adapter/outboundgroup/loadbalance.go)。

## 私有部署的配置变更

已取消的 JP 路线及其空余专用组保持移除，历史账本保留。三条原来由 JP 承载的规则改为同一个隐藏的自动回退组：普通 US3 优先，失效时使用默认选择组。这个组只被分流规则引用，没有加入默认选择组自身，因此不存在循环。

回退根据客户端健康检查和拨号故障触发，不是任意 HTTP 错误的自动重试。该变化不改 SG／US 原有三节点负载均衡、下载策略、登录策略、独立节点选择和住宅线路权限。Shadowrocket 当前提供节点列表，不承载 Clash 策略规则；其节点列表没有因本轮规则修改而变化。

实际域名、私有源、用户授权与订阅链接只保存在运行端和已忽略的运维文件，不写入公开项目示例。每个人更新自己的远程订阅即可取得新规则。

## 验证

- 门户 80 项单元及接口测试通过。
- 隔离 Edge 浏览器通过用户端与七个管理页面的回归，包括 US1／US2／US3 分类、排序、390／1920／3840px 布局、隐藏备用及身份不变。已查看虚构数据截图。
- 本机隔离启动 Mihomo v1.19.32，使用两个回环 HTTP 代理和虚构流量，分别验证三种规则匹配、US3 优先、断开后选择默认、恢复后重新使用 US3；无关域名走默认。没有调用正在运行的客户端控制器。
- 6 个现有用户的 Clash／Stash／Shadowrocket 共 18 份实际订阅，在本地服务与公网端分别核对。只增加三条规则和一个隐藏回退组，其余配置结构、授权、凭据、签名密钥和历史总账／分类字节不变。
- 同轮检查部署仓库，修正首次配置校验创建访问日志的所有者问题。Linux 上 28 项测试及真实 root／Xray 用户的日志可写性检查通过；没有重启其他生产节点。

完整的端点、脱敏结果和可恢复备份位于工作区 `.agents` 与已忽略的 `private/` 运维目录。
